# OST Finder · Spider

OSINT-приложение для исследования публичных источников: ник, домен, email, IP или обычная тема. Собирает найденные ссылки и сохраняет отчёты JSON/Markdown. API-ключи не требуются.

**Открытый репозиторий проекта:** [prostoodin1/OST_find](https://github.com/prostoodin1/OST_find). Исходники и релизы доступны всем. Ранее выпущенные версии перенесены сюда из Ideas с проверкой SHA-256.

## Качество поиска

Введите `Иван Иванов | инженер Москва` или заполните поле контекста. Имена ищутся точной фразой; дополнительные запросы с `site:` и `filetype:` для Google и точный запрос для Yandex доступны как подсказки. Эти ссылки не считаются найденными свидетельствами. Программа не устанавливает личность по одному ФИО или нику.

Вкладка **Качество и сводка** содержит уникальные URL, предупреждения о тёзках, слабых совпадениях и спаме, очищенные выдержки до трёх публичных страниц, автора/дату/заявленный canonical, если они доступны. Почти одинаковый текст отмечается как возможная перепечатка. Основная таблица сортируется по баллу силы свидетельств; нулевое совпадение и возможный спам скрываются из неё, но остаются в сводке и отчёте.

Сводка включает сопоставление фрагментов между доменами, хронологию и возможные числовые расхождения со ссылками `[S1]`, `[S2]`. Балл — эвристика, а не вероятность истинности. Одинаковый текст может быть перепечаткой; числовое расхождение требует сравнения дат и контекста. Отсутствие автоматических предупреждений не доказывает достоверность.

Бюджет сети и браузера — по 20 секунд параллельно, очистки — до 5 секунд, необязательной LLM — до 4 секунд. Возвращаются частичные результаты с отметками тайм-аута. Цель — 15–30 секунд; для любой сети, DNS и холодного запуска Chromium это не гарантируется. Очистка учитывает robots.txt и ограничивает размер страниц; JS-only страницы могут не дать выдержки. Браузер собирает DOM независимо.

429/503 включают паузу источника с учётом `Retry-After`. Обхода ограничений ротацией адресов нет. Собственный прокси для источников: переменная `OST_SEARCH_PROXY`. Исключения источников выводятся без URL запросов и без ключей. Новый источник: `register_source(name, fetcher)`, где `fetcher(query, limit)` возвращает `Finding`.

**Brave Web Search API** включается при наличии `OST_BRAVE_KEY`. Wayback возвращает найденный снимок для доменного запроса. Google Custom Search закрыт для новых клиентов и прекращает обслуживание 1 января 2027; Bing Search API закрыт 11 августа 2025. Эти устаревшие API не добавлены; HTML-поиск Bing и поисковые ссылки Google остаются. См. [Bing](https://learn.microsoft.com/en-us/lifecycle/announcements/bing-search-api-retirement), [Google](https://developers.google.com/custom-search/v1/overview), [Brave](https://api-dashboard.search.brave.com/app/documentation/web-search/get-started).

### Необязательный LLM

По умолчанию LLM отключён: **0 запросов, ключи не нужны**. Выберите Ollama или OpenRouter и явно укажите модель. На поиск отправляется **один запрос**: до 12 выдержек по 600 символов, максимум 350 выходных токенов, без инструментов и повторных попыток. Ollama использует локальный `http://127.0.0.1:11434/api/chat`; OpenRouter — ключ `OST_OPENROUTER_KEY`. Приложение не выбирает платную модель за пользователя.

**OpenRouter получает запрос, контекст и выдержки.** Включайте только если согласны передавать их провайдеру. Ключ не записывается в отчёт/настройки. Ответ модели может выбрать только существующие ID релевантных/неоднозначных выдержек; новые факты и адреса не принимаются. LLM-подсказка не повышает балл и не устанавливает личность. Документация: [Ollama](https://docs.ollama.com/api/chat), [OpenRouter](https://openrouter.ai/docs/api_reference/overview).

### Приватность результатов

Снимите **Сохранять отчёты на этом компьютере**, чтобы не записывать запрос/результаты на диск. В CLI используйте `--no-save`. По умолчанию прежнее поведение сохранено: локальные отчёты включены. Серверного хранилища и кеша запросов нет. Общедоступность источника не означает отсутствие персональных данных; пользователь управляет сохранением. Ранее сохранённые файлы не удаляются при выключении флажка.

## Полное автообновление Windows

С **0.6.0** EXE проверяет публичный `prostoodin1/OST_find/releases/latest` при запуске. GUI: кнопка **Обновить** и сохраняемый флажок автоматической установки. Проверка/загрузка идут в фоне; установка ждёт завершения поиска. CLI: `--check-update`, `--update`, `--no-auto-update`. Настройка GUI хранится в `%LOCALAPPDATA%/OST Finder/updates.json` и также учитывается CLI.

Цикл: проверка стабильной версии → выбор GUI/CLI и standalone/portable → HTTPS-загрузка → размер и SHA-256 из метаданных GitHub → ожидание закрытия процесса → бэкап → замена → проверка запуска → перезапуск. Portable заменяет `_internal` вместе с EXE; `reports` и посторонние файлы сохраняются. При сбое замены или проверки запуска прежние файлы восстанавливаются. Portable EXE должен сохранять исходное имя; standalone можно переименовать.

Без прав записи рядом с EXE обновление не устанавливается; повышение прав не запрашивается. Бэкап `OST-update-backup-*` остаётся рядом с EXE, лог — в `%TEMP%/OST-update-*/install.log`. SHA-256 защищает пакет относительно метаданных GitHub; это не независимая подпись разработчика. Учётные данные GitHub не нужны. [GitHub Release Assets](https://docs.github.com/en/rest/releases/assets).

**0.5.0 ещё не содержит updater:** один раз установите 0.6.0 вручную. Следующие выпуски будут устанавливаться автоматически. Исходники обновляйте через `git pull` — updater не заменяет рабочую копию.

## Spider: интерфейс и браузер

Тёмный интерфейс с голубыми и зелёными акцентами вдохновлён рабочими инструментами Kali. Это самостоятельное приложение с собственным дизайном.

1. Введите запрос и нажмите **Начать поиск**.
2. Откроется отдельное небольшое окно приватного браузера. Каркасный неоновый паук с восемью суставчатыми лапами движется между элементами страницы.
3. Приложение параллельно запрашивает публичные источники и извлекает реальные ссылки из DOM поисковой выдачи браузера.
4. Лапы опираются на реальные DOM-прямоугольники: выбранный элемент подсвечивается, после контакта захваченный текст или URL появляется в таблице и поднимается к счётчику CAPTURED. Браузер посещает до двух найденных страниц и прокручивает их во время сбора. Для одного прохода ограничены время и число захватов.
5. После завершения можно сразу вводить новый запрос. Двойной щелчок по результату открывает ссылку в том же приватном браузере.

Кнопка **Мини-браузер** переключает отдельное окно и встроенную панель. **Как искать** показывает примеры. Недоступные сайты, CAPTCHA и сетевые ошибки записываются в журнал; остальные источники продолжают работать.

| Ввод | Что ищется |
| --- | --- |
| `@username` | публичные профили и репозитории |
| `example.com` | веб, DNS, RDAP, сертификаты, urlscan, архив |
| `name@example.com` | публичные упоминания и Gravatar |
| `8.8.8.8` | IP RDAP, reverse DNS, urlscan и веб |
| `open source video editor` | обычная тема по публичным источникам |

Источники: DuckDuckGo, Bing, GitHub, GitLab, Hacker News, Wikipedia, Stack Overflow, DNS, RDAP, Certificate Transparency, urlscan.io, Gravatar; также доступны поисковые и Wayback-ссылки. Ссылки для ручного поиска отмечены `Search shortcut` и не означают найденное совпадение.

## Что означает инкогнито

Встроенный браузер использует отдельный **off-the-record** профиль Qt WebEngine: cookies и кэш остаются в оперативной памяти и не переносятся в следующий запуск. Приложение не использует ваши профили Chrome/Edge или их авторизацию. [Документация Qt](https://doc.qt.io/qt-6/qwebengineprofile.html#QWebEngineProfile).

Это не VPN и не Tor: сайты видят обычное сетевое соединение. JSON/Markdown-отчёты намеренно сохраняются в `reports` рядом с EXE; их папку можно изменить кнопкой **Куда сохранять…**. Cookies могут использоваться между поисками в рамках одного запуска приложения.

## Терминал

Запустите `OST_find_0.6.0_x64.exe`. Постоянная сессия `OST_find>` поддерживает `help`, `clear`, `exit`. Для одного запроса:

```powershell
./OST_find_0.6.0_x64.exe --limit 5 "example.com"
```

## Из исходников

Python 3.10+ для терминала и Python с подходящим колесом PySide6 для GUI.

```powershell
python -m pip install -r requirements.txt
python ost_find.py
```

Оконный вариант:

```powershell
python -m pip install -r requirements-gui.txt
python ost_spider.py
```

Для тестов и сборки дополнительно установите `python -m pip install -r requirements-dev.txt`. Проверки: `python -m pytest -q` (для браузерных тестов нужен PySide6). Сборка Windows: `./build.ps1` для терминала, `./build-gui.ps1` для Spider. Параметр `-Python` позволяет указать Python из своего виртуального окружения.

Полностью индексировать весь интернет приложение не может. Доступность выдачи зависит от самих источников; CAPTCHA и ограничения не обходятся. Проект работает с публичными страницами.
